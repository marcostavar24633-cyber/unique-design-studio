# Unique Design Studio

Отдельный проект для разработки уникальных визуальных концепций и дизайн-систем сайтов.

Начиная с версии 0.2 спецификация [`unique-design-architecture.md`](design-system/unique-design-architecture.md) **исполняется кодом**: генератор строит Design Brief и Design DNA, выбирает архитектуру главной страницы, проверяет её на шаблонность и собирает самостоятельный HTML.

## Как пользоваться

Откройте `index.html` через любой статический сервер (или GitHub Pages):

```bash
npx http-server@14.1.1 . -p 5180
```

1. Введите бренд и описание бизнеса, при желании город, тон и архитектуру.
2. Нажмите «Собрать концепцию». Слева появятся Design DNA, проверка перед выдачей и Design Brief с гипотезами, справа живое превью (десктоп, планшет, телефон, 320 px).
3. Экспорт: «Скачать HTML», «JSON для Landing Studio» или «Скопировать промт».

Кнопка «Демо: 10 ниш подряд» прогоняет все проекты из реестра и показывает, как генератор разводит соседние сайты.

## Что реализовано (раздел 11 спецификации)

| Условие интеграции | Где |
|---|---|
| 1. Формируются Design Brief и Design DNA | `buildDesignBrief`, `createConcept` в `engine/design-engine.js` |
| 2. Они используются при создании структуры и HTML | `renderHomepage`: у каждой из 10 архитектур своя разметка hero, навигация и порядок секций |
| 3. Концепция выводится в результате и промте | Панель студии, `contractOf` (контракт из раздела 8), `toPrompt` |
| 4. Антишаблонная проверка | `uniquenessCheck`: соседний проект не может повторить одновременно архитектуру, позицию визуала и типографику. Также сдвигаются близкие палитры и совпадающие шрифты, а тёмный фон с золотом не выдаётся по умолчанию |
| 5. Совместимость с форматом проекта и импортом JSON | `toLandingStudioProject` → `{format:"LandingStudioProject", version:1, project:{name,data}}`; `designArchitecture` из enum Landing Studio, расширенные поля сохраняются при импорте |

### 10 архитектур

Product First · Editorial / Magazine · Immersive Fullscreen · Asymmetric Canvas · Catalog / Marketplace · Split Utility · Storytelling Scroll · Modular Grid · Brutalist / Experimental · Minimal Conversion.

Архитектуры различаются композицией, а не только цветом: у каждой своя разметка первого экрана, тип навигации (мастхед, боковой индекс, поиск в шапке, рельс глав, плитки…), форма карточек, шрифтовая пара и поведение движения. При ручном выборе архитектуры, совпадающей с соседним проектом, используется зеркальный вариант с другой шрифтовой парой.

### Чего генератор не делает

- Не выдумывает цены, отзывы, сертификаты, адреса, телефоны и гарантии. На их месте стоят пометки «уточнить», а гипотезы перечислены в брифе.
- Не отправляет заявки: форма валидируется и сообщает, что отправку нужно подключить к мессенджеру или почте владельца.
- Не подбирает фотографии: вместо них стоят подписанные заглушки с направлением съёмки из Design DNA.
- Определение ниши работает по ключевым словам. Нераспознанная ниша получает общий сервисный профиль, и это отмечается в гипотезах.

## Проверки

```bash
npm test
```

13 тестов: контракт раздела 8, выбор архитектуры по нише, отсутствие повторов hero у 20 проектов подряд, зеркальный режим, рендер всех 10 архитектур (lang, viewport, reduced motion, focus, skip-link, один h1, подписи полей), отсутствие ширин больше 320 px, контраст WCAG для всех тонов, запрет «тёмного с золотом» по умолчанию, отсутствие выдуманных цен и телефонов, совместимость с Landing Studio, детерминированность.

`npm run examples` пересобирает `examples/`: 10 страниц для проектов из реестра, сгенерированных подряд.

## Состав

- `index.html`: интерфейс студии.
- `engine/design-engine.js`: генератор (браузер и Node, без зависимостей).
- `tests/engine.test.mjs`: тесты уникальности, адаптивности и доступности.
- `examples/`: сгенерированные главные страницы.
- `design-system/`: спецификация, токены, компоненты, профили проектов, motion.
