# Unique Design Studio

Генератор самостоятельных главных страниц. По описанию проекта он сначала проектирует концепцию — **Design Brief** и **Design DNA**, — затем собирает под неё композицию и HTML и проверяет результат на шаблонность, доступность и адаптивность.

Продукт реализует спецификацию [`design-system/unique-design-architecture.md`](design-system/unique-design-architecture.md): не «один шаблон + другие тексты и цвета», а отдельная архитектура первого экрана, навигация, палитра, типографика и порядок секций для каждого проекта.

## Что внутри

| Часть | Где | Что делает |
| --- | --- | --- |
| Движок | `src/engine/` | Brief → DNA → HTML → проверка. Без зависимостей, работает в Node и в браузере |
| Веб-студия | `studio/` | Редактор проекта, живой предпросмотр (320 / 768 / вся ширина), концепция, проверка, реестр, импорт и экспорт JSON |
| CLI | `bin/uds.js` | Генерация из JSON, концепция, проверка, промт для AI-помощника |
| Дизайн-система | `design-system/` | Токены и компоненты ядра; генератор встраивает их в каждую страницу |
| Примеры | `examples/` | 7 проектов из реестра брендов: ДомА Тех, Photograf, ПЕНКА, РАКОВАРНЯ 73, Hair, магазин телескопов, Слопай букет |
| Тесты | `tests/` | Контракт, уникальность, совместимость форматов, доступность, браузерная проверка адаптивности |

## Быстрый старт

Нужен Node.js 20 или новее. Устанавливать ничего не требуется.

```bash
npm start
```

Откроется студия на `http://localhost:4173/studio/`. Выберите пример или заполните «Бренд» и «Нишу» — страница и концепция обновляются по мере ввода.

Генерация из командной строки:

```bash
node bin/uds.js generate examples/penka.json --out out/penka
```

В папке появятся `index.html` (самодостаточная страница без внешних ресурсов), `concept.json` (Design Brief, Design DNA, структура, антишаблонная проверка) и `project.json` (экспорт проекта). Код выхода `1` означает, что проверка перед выдачей не пройдена.

Остальные команды:

```bash
node bin/uds.js init my-project.json     # заготовка проекта
node bin/uds.js concept my-project.json  # только концепция
node bin/uds.js audit my-project.json    # только проверка
node bin/uds.js prompt my-project.json   # промт с концепцией для AI-помощника
node bin/uds.js archetypes               # список архитектур
```

## Как это работает

1. **Ниша.** По полю `niche` и описанию определяется профиль бизнеса (18 профилей: магазины, кофейни, салоны, портфолио, услуги, IT и др.). Если ниша не распознана, используется универсальный профиль, и это записывается в гипотезы.
2. **Design Brief.** Бизнес, аудитория, целевое действие, характер бренда, приоритет контента, ограничения. Всё, чего нет в данных, помечается как гипотеза. Цены, отзывы, адреса, гарантии и сертификаты не выдумываются: нет данных — нет блока.
3. **Архитектура.** Из 10 архитектур выбирается основная и вспомогательная — по нише и сигналам контента (число позиций, цены, изображения, форма заявки). Выбор объясняется в `selectionRationale`.
4. **Визуальная система.** Палитра (16 цветовых направлений, контраст всех текстовых пар не ниже 4.5:1), типографика (8 характеров на системных шрифтах), форма, кнопки, навигация (6 паттернов), движение.
5. **Антишаблонная проверка.** «Отпечаток» проекта сравнивается с двумя предыдущими из реестра. Нельзя одновременно повторять архитектуру hero, расположение визуала и характер типографики. При совпадении сначала пересобирается композиция, и только потом меняются детали.
6. **HTML.** В страницу попадают только стили выбранной архитектуры и только секции, для которых есть контент.
7. **Проверка перед выдачей.** Один `h1`, рабочие якоря и ссылки, подписи полей, `alt`, видимый фокус, `prefers-reduced-motion`, контраст, наличие способа связи, отсутствие выдуманных цен.

### Архитектуры

| id | Название | Первый экран |
| --- | --- | --- |
| `product-first` | Product First | Главный товар и покупка в центре |
| `editorial` | Editorial / Magazine | Журнальная типографика и колонки |
| `immersive` | Immersive Fullscreen | Полноэкранный визуал, текст поверх |
| `asymmetric` | Asymmetric Canvas | Асимметричная сетка с наложением |
| `catalog` | Catalog / Marketplace | Поиск и плитки разделов сразу |
| `split-utility` | Split Utility | Предложение и инструмент действия |
| `storytelling` | Storytelling Scroll | Заявление и оглавление глав |
| `modular-grid` | Modular Grid | Сетка модулей-входов |
| `brutalist` | Brutalist / Experimental | Гигантская типографика в рамке |
| `minimal` | Minimal Conversion | Одно предложение, один CTA |

У каждой архитектуры 2–3 варианта расположения визуала.

## Совместимость с Landing Studio

JSON из редактора Landing Studio импортируется без правок: списки-массивы `[["Заголовок","Текст"]]`, `palette: "Тёмная" | "Светлая"`, `accent`, `designArchitecture` (`catalog`, `editorial`, `immersive`, `service`, `modular`). Значение `designArchitecture` трактуется как семейство, внутри которого архитектура подбирается по нише. Проекты без этого поля работают в автоматическом режиме.

Экспорт читается обоими продуктами: в нём остаются поля старого формата, неизвестные движку поля (`marketResearch`, `researchSources` и др.) сохраняются как есть, а концепция добавляется в поле `concept`.

Полное описание полей — в [`docs/project-format.md`](docs/project-format.md).

## Реестр и уникальность

- **CLI** хранит отпечатки в `.uds-registry.json` в текущей папке (`--registry <файл>` — другой путь, `--no-registry` — без сравнения).
- **Студия** хранит реестр в браузере: кнопка «В реестр» сохраняет проект, вкладка «Реестр» показывает сходство с текущим.

Проверка сравнивает проекты между собой внутри одного реестра. Она не сравнивает результат с чужими сайтами в интернете.

## Использование как библиотеки

```js
import { generate } from './src/engine/index.js';

const { html, concept, audit, registry } = generate(project, { registry: previous });
```

`buildConcept`, `renderSite`, `auditSite`, `buildPrompt`, `exportProject` доступны по отдельности.

## Тесты и сборка

```bash
npm test
```

29 тестов: контракт концепции, выбор архитектуры по нишам, уникальность соседних проектов, совместимость форматов, экранирование, доступность разметки, контраст палитр.

```bash
npm run test:e2e
```

Браузерная проверка (нужен Playwright с Chromium): все архитектуры и расположения на ширинах 320, 768 и 1280 — без горизонтальной прокрутки, с видимым фокусом, с учётом reduced motion и работой без JavaScript.

```bash
npm run build
```

Собирает в `dist/` статический сайт: студию и галерею примеров. Workflow `.github/workflows/pages.yml` публикует его на GitHub Pages при пуше в `main` (в настройках репозитория нужно включить Pages с источником «GitHub Actions»).

После правки `design-system/tokens.css` или `components.css` запустите `npm run sync-core` — он обновит встроенную в движок копию ядра.

## Ограничения

- Тексты продукт не пишет: он проектирует и верстает. Для текстов команда `prompt` (или кнопка «Промт для AI» в студии) выдаёт промт с концепцией; ответ модели импортируется как JSON.
- Фотографии не генерируются. Пока изображений нет, на их месте стоит абстрактный графический мотив, а проверка выдаёт предупреждение.
- Используются системные шрифты, поэтому начертание заголовков зависит от устройства.
- Форма отправляется на ваш `formAction` или открывает почтовую программу; собственного сервера приёма заявок нет.
- Контакты в примерах — заглушки на `example.com`.
