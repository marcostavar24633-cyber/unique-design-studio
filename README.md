# Unique Design Studio

Студия проектирования самостоятельных визуальных концепций сайтов. Цель — не перекрашивать один шаблон, а создавать для каждой ниши собственную архитектуру, графический язык и интерфейсную систему.

## Движки

- `src/design-director.js` — Design Director: анализирует нишу, аудиторию, цель и приоритеты; выбирает одну из 10 архитектур главной страницы.
- `src/visual-identity.js` — Visual Identity Engine: формирует палитру, типографику, геометрию, сетку, ритм отступов, графический язык и поведение интерфейса.
- `src/layout-engine.js` — Layout Engine: превращает концепцию и визуальную систему в адаптивный план страницы, связывает секции с компонентами и генерирует базовый CSS.\n- `src/component-renderer.js` — Component Renderer: собирает семантический HTML, выводит карточки, изображения, CTA и формы-макеты, применяет токены визуальной идентичности.
- `design-system/` — архитектурные правила, токены, компоненты и motion-принципы.

## Быстрый запуск

Требуется Node.js 18 или новее.

```bash
npm test
npm run check
```

## Пример использования

```js
import { createDesignConcept } from "./src/design-director.js";
import { createVisualIdentity } from "./src/visual-identity.js";

const concept = createDesignConcept({
  businessType: "магазин телескопов",
  businessName: "Astro",
  audience: "начинающие астрономы и любители наблюдений",
  primaryGoal: "purchase",
  contentPriority: ["каталог", "подбор", "сравнение характеристик"]
});

const visualIdentity = createVisualIdentity({ concept });
console.log(visualIdentity);
```

## Принцип уникальности

1. Сначала определяется задача бизнеса и сценарий посетителя.
2. Затем выбирается архитектура страницы, а не готовая цветовая тема.
3. На её основе создаётся визуальная система: цвет, шрифты, геометрия, сетка, изображения и motion.
4. Концепция сохраняется как сигнатура для сравнения с будущими проектами.
5. Финальная уникальность подтверждается только проверкой отрендеренной страницы.

## Текущие ограничения

Движки работают локально на JavaScript и не требуют внешнего API. Они генерируют структурированные спецификации, но ещё не являются полноценным визуальным редактором и не рендерят готовый сайт сами по себе. Следующий этап — Layout/Component Renderer и интерактивный предпросмотр.

## Разработка

Новые функции создаются в отдельных ветках `feature/*`. `main` не меняется без проверки и отдельного слияния.
