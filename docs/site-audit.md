# SEO и технический аудит

Модуль `src/site-audit.js` выполняет статические проверки сгенерированного HTML. Он работает локально, без API и сетевых запросов.

## Что проверяется

- наличие Title и meta description, ориентировочная длина;
- наличие одного основного H1 и базовая последовательность H1–H6;
- заполненность ALT у изображений (пустой ALT выделяется отдельно, так как может быть корректен для декоративных изображений);
- Open Graph title, description и image;
- canonical URL и HTTPS-схема;
- атрибут языка HTML;
- повторяющиеся ID и ссылки-якоря на отсутствующие элементы;
- демонстрационные формы, которым ещё нужен обработчик отправки.

Результат содержит условный балл, число ошибок и предупреждений, метрики и список рекомендаций. Это внутренняя эвристическая оценка, а не оценка Google, Lighthouse или гарантия позиций в поиске.

## Настройки в студии

После генерации откройте «Шапка и контакты» → «SEO и предпросмотр в поиске»:

- SEO Title;
- Meta Description;
- Canonical URL;
- Open Graph image URL.

OG Title и OG Description по умолчанию используют SEO Title и Meta Description. Canonical не подставляется автоматически: сначала выберите основной домен и точный URL страницы. Для OG image укажите доступный абсолютный URL изображения по HTTPS.

## Ограничения

Проверка анализирует только HTML, который генерирует студия. Она не загружает сайт по сети, не проверяет HTTP-статусы внешних изображений и ссылок, Core Web Vitals, серверные заголовки, sitemap.xml, robots.txt, фактическую индексацию, мобильную скорость или доступность реального опубликованного сайта. Перед запуском нужен отдельный аудит опубликованного домена.

## Адаптивность, доступность и ресурсы

Аудит также анализирует CSS и разметку:

- наличие media query для узких экранов;
- :focus-visible для клавиатурной навигации;
- prefers-reduced-motion;
- базовые семантические области header, main, footer;
- meta viewport и язык документа;
- доступные имена ссылок, безопасный rel для target=_blank, подписи полей форм;
- наличие размеров width/height у изображений;
- встроенные изображения, превышающие ориентир 300 КБ;
- CSS-размер в байтах и потенциальные признаки горизонтальной прокрутки;
- базовое наличие интерактивных областей высотой от 44–48 px.

Первое изображение Hero выводится с приоритетной загрузкой, изображения ниже первого экрана — с lazy loading. Это помогает избежать лишней задержки для главного визуального элемента, но не является измерением LCP.

## Что аудит не может подтвердить

Статический анализ не открывает сайт в реальном браузере и не может достоверно подтвердить отсутствие горизонтального переполнения, корректность всех breakpoint на конкретных устройствах, контрастность, реальный размер области касания, CLS/LCP/INP, скорость сети, сжатие и фактическую доступность удалённых изображений. Для этого нужен браузерный прогон и Lighthouse/PageSpeed на опубликованном адресе. Балл в интерфейсе — внутренняя диагностическая оценка, не Google Lighthouse score.
- Проверяются доступные названия кнопок: текст, title или aria-label.
