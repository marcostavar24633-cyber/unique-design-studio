# Анализатор сайтов и библиотека шаблонов

Документ описывает, как студия получает данные чужих публичных страниц, что именно она измеряет,
и как подключить необязательный анализатор-сервер на Cloudflare Workers.

## 1. Архитектура

```
GitHub Pages (frontend)                      Cloudflare Worker (необязателен)
┌──────────────────────────────┐   GET /fetch?url=…   ┌───────────────────────────┐
│ studio/templates.html        │ ───────────────────▶ │ worker/site-fetch.js      │
│  ├─ site-analysis.js (разбор)│ ◀─────────────────── │  только загрузка HTML/CSS │
│  ├─ library.js (профили)     │      JSON с текстом  │  без cookie и секретов    │
│  └─ localStorage (библиотека)│                      └───────────────────────────┘
└──────────────────────────────┘
        ▲ JSON импорт / экспорт
```

- **Frontend** — статический сайт на GitHub Pages. Весь разбор разметки и стилей выполняется в браузере
  модулем `src/engine/site-analysis.js` (без DOM, тот же код проходит тесты в Node).
- **Хранение** — только `localStorage` браузера (ключ `uds:template-library:v1`). Серверной базы данных нет.
- **Перенос** — экспорт и импорт JSON.
- **Worker** — нужен только чтобы обойти ограничение CORS: браузер не может сам прочитать чужой сайт.
  Worker ничего не анализирует и не хранит, он возвращает текст одной публичной страницы или файла стилей.

Страница библиотеки **никогда** не запрашивает сторонние сайты напрямую через `fetch` — это проверяется тестом.

## 2. Три способа получить данные

| Способ | Что нужно | Что получится |
|---|---|---|
| Анализатор-сервер | Развёрнутый Worker и его адрес в настройках | HTML страницы + до 6 файлов стилей, полный анализ |
| HTML-код страницы | Вставить разметку или загрузить сохранённый файл | Полный анализ структуры; стили — если они есть в коде |
| Ручной ввод | Ничего | Пустой профиль, который заполняет пользователь |

**По умолчанию Worker не подключён.** Пока его адрес не задан, интерфейс прямо сообщает об этом и предлагает
вставить HTML или заполнить профиль вручную. Если ни одну страницу получить не удалось, профиль не создаётся:
студия не показывает выдуманный анализ.

Самый точный ручной способ — команда для консоли браузера (кнопка «Скопировать команду» в интерфейсе).
Она копирует готовую разметку открытой страницы вместе с правилами доступных таблиц стилей.
Это данные, которые браузер пользователя и так получил, — никакие защиты при этом не обходятся.

## 3. Что измеряется

Анализ статический: студия читает разметку и стили, но не «смотрит» на страницу и не исполняет её скрипты.

- **Структура** — порядок и типы блоков, навигация, группы карточек, формы и их поля, кнопки действия,
  функциональные элементы (поиск, корзина, слайдер, аккордеон, карта, чат и т. д.).
- **Визуальная система** — палитра с ролями, контраст текста и фона, гарнитуры, размеры заголовков,
  grid/flex, ширина контейнера, контрольные точки, шаг отступов, скругления, тени.
- **UX** — путь пользователя по блокам, расположение действий, способы связи, признаки мобильной адаптации
  и список найденных проблем (нет viewport, нет alt, поля без подписи, слабый контраст и др.).
- **Контент** — типы заголовков, подача преимуществ, устройство первого экрана, типы карточек, логика CTA.

### Ограничения, о которых интерфейс сообщает сам

- Нет стилей (вставлен только исходный HTML, внешние CSS не получены) → визуальная система **не заполняется**.
- Сайт собирается JavaScript-ом (в исходном HTML пустой `<div id="root">`) → предупреждение и совет
  скопировать готовую разметку из браузера.
- Вместо страницы пришла проверка «я не робот» или отказ → страница помечается как неполученная.
- Поле «Близкие архитектуры» и блок «Идеи» — это оценка и черновик студии, а не измерение; так и подписаны.

Каждое поле профиля имеет метку происхождения: «из анализа», «вручную» или «не заполнено».
Изменённое пользователем поле получает метку «вручную».

## 4. Анализатор-сервер (Cloudflare Worker)

Код: `worker/site-fetch.js`, конфигурация: `worker/wrangler.toml`.

> **Статус: код написан и покрыт тестами, но Worker не развёрнут.** В этом репозитории нет ни аккаунта
> Cloudflare, ни адреса сервера. Развёртывание выполняет владелец проекта на своём аккаунте.

### Что делает и чего не делает

- Принимает только `GET /fetch?url=…&kind=html|css` и `GET /health`.
- Отвечает только сайтам из списка `ALLOWED_ORIGINS` (по умолчанию — сайт студии на GitHub Pages).
- Принимает только `http/https`-адреса по имени хоста: IP-адреса, `localhost`, внутренние зоны, нестандартные
  порты и адреса с логином/паролем отклоняются. Каждое перенаправление проверяется заново (не больше трёх).
- Перед загрузкой страницы читает `robots.txt` — для исходного адреса и для каждого адреса в цепочке
  перенаправлений — и не идёт туда, куда владелец сайта запретил.
- Представляется честным `User-Agent`, не передаёт cookie и заголовки авторизации.
- **Не обходит** авторизацию, CAPTCHA, проверки «я не робот», paywall: ответы `401/402/403/407/429/451`
  и заголовок `cf-mitigated` возвращаются как отказ `protected`, повторных попыток нет.
- Ограничивает объём (HTML — 1,5 МБ, CSS — 1 МБ) и время ожидания (10 секунд).
- Не содержит секретов: ни в коде, ни в `wrangler.toml` нет ключей, и они не нужны.

### Проверка тарифов и ограничений (выполнена 16.11.2026)

Официальная документация Cloudflare (`developers.cloudflare.com`) из среды разработки была недоступна,
поэтому цифры ниже взяты из вторичных источников и **должны быть сверены перед развёртыванием**:

| Параметр бесплатного плана | Значение | Надёжность |
|---|---|---|
| Запросов в сутки | 100 000 | подтверждается несколькими независимыми источниками |
| Время CPU на запрос | 10 мс (в одном источнике — 30 мс) | **не подтверждено**, источники расходятся |
| Подзапросов на запрос | 50 | **не подтверждено** официальным источником |
| Размер скрипта | 1 МБ | из вторичного источника |

Страницы для сверки: `https://developers.cloudflare.com/workers/platform/limits/` и
`https://developers.cloudflare.com/workers/platform/pricing/`.

Worker спроектирован с запасом под самые строгие из этих значений:

- один вызов = не больше 8 исходящих запросов (страница, до трёх перенаправлений и `robots.txt` каждого нового хоста);
- файлы стилей запрашиваются отдельными вызовами со стороны браузера (до 6 на страницу);
- разбор HTML и CSS выполняется в браузере, поэтому время CPU Worker тратится только на пересылку байтов;
- анализ сайта из 9 страниц — это примерно 9 × (1 + 6) = 63 вызова, то есть суточного лимита хватает
  более чем на тысячу анализов.

Техническая совместимость: используются только стандартные `fetch`, `Request`, `Response`, `URL`,
`AbortController`, `TextDecoder` и потоковое чтение тела ответа. Тот же файл без изменений исполняется
в Node 20+ (так он и тестируется: `tests/worker.test.mjs`, `tests/e2e/templates.mjs`).

### Развёртывание

1. Зарегистрируйте аккаунт Cloudflare и сверьте лимиты бесплатного плана по ссылкам выше.
2. Установите Wrangler и войдите: `npm i -g wrangler`, затем `wrangler login`.
3. В `worker/wrangler.toml` проверьте `ALLOWED_ORIGINS` — там должен быть адрес сайта студии.
4. Из папки `worker` выполните `wrangler deploy`. Команда напечатает адрес вида
   `https://uds-site-fetch.<аккаунт>.workers.dev`.
5. В студии: «Библиотека шаблонов» → «Анализатор-сервер» → «Настройки» → вставьте адрес →
   «Сохранить и проверить». Адрес сохраняется только в вашем браузере.

### Защита от посторонних вызовов

Проверка заголовка `Origin` защищает только от чужих сайтов в браузере. Программа вне браузера может подставить
любой `Origin`, поэтому развёрнутый Worker — это общедоступная точка, которой можно расходовать ваш суточный лимит.
Секретный ключ здесь не поможет: сайт студии статический, и любой ключ в нём был бы виден всем.

Что с этим делать:

- включить ограничение частоты запросов. Worker уже поддерживает привязку `RATE_LIMITER`
  (Workers Rate Limiting): если она настроена, запросы сверх лимита с одного IP получают ответ 429.
  Синтаксис привязки в `wrangler.toml` сверьте с актуальной документацией Cloudflare;
- либо настроить правило ограничения частоты в панели Cloudflare;
- не публиковать адрес Worker без необходимости.

Без этих мер ущерб ограничен: Worker отдаёт только публичные страницы, не ходит во внутренние сети
и упирается в суточный лимит бесплатного плана.

## 5. Формат библиотеки

Экспорт: `{ app, kind: "template-library", version: 2, exportedAt, templates: [...] }`.

Запись шаблона:

```json
{
  "formatVersion": 2,
  "id": "…", "name": "…", "category": "Услуги и бизнес", "business": "мебель на заказ",
  "url": "https://…", "pages": ["https://…"], "notes": "…",
  "createdAt": "…", "updatedAt": "…",
  "status": "source-saved | analyzed | manual",
  "analysis": { "source": "worker | html | manual | none", "analyzedAt": "…", "pages": [], "warnings": [] },
  "profile": { "pageStructure": [], "blocks": [], "navigation": [], "cards": [], "forms": [], "cta": [], "features": [],
               "palette": [{ "hex": "#f6f1e8", "role": "фон" }], "contrast": [], "typography": [], "headingSizes": [],
               "composition": [], "grid": [], "spacing": [], "radii": [], "hierarchy": [],
               "userPath": [], "actions": [], "navUx": [], "mobile": [], "issues": [],
               "headingTypes": [], "benefits": [], "offer": [], "cardTypes": [], "ctaLogic": [], "ideas": [] },
  "traits": { "archetypes": [], "sectionOrder": [], "nav": "", "shape": "", "typeCharacter": "", "mode": "" },
  "provenance": { "blocks": "auto | manual" }
}
```

Совместимость: записи первой версии (`{id, url, pages, name, category, notes, createdAt, status}` из PR №36)
читаются из того же ключа хранилища и из файлов импорта без потерь; при первом сохранении они дополняются
пустым профилем. Импорт принимает массив, объект с полем `templates` или один шаблон.

## 6. Как профили попадают в новый проект

См. раздел «Библиотека шаблонов в генераторе» в `README.md`. Коротко: в проект передаются только
структурные, UX- и контентные принципы. Палитра, гарнитуры, адрес и тексты источника в генератор не передаются,
а композиция первого экрана источника намеренно не повторяется.
