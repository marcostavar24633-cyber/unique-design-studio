# Merge Engine — автономная проверка и слияние Pull Request

Состояние на 17.11.2026.

## Как устроено

| Часть | Файл | Что делает |
|---|---|---|
| Правила | `src/merge/rules.mjs` | 10 обязательных условий слияния. Общие для исполнителя и панели. Неизвестный факт считается невыполненным условием. |
| Анализ git | `scripts/merge-engine/git-analysis.mjs` | Отставание от main, конфликты (`git merge-tree`), что слияние уберёт из main (строки, файлы, экспорты), секреты и персональные данные в добавляемых строках, тесты и сборка на результате слияния во временной копии. |
| GitHub | `scripts/merge-engine/github.mjs` | REST API. Токен — только из `GITHUB_TOKEN`/`GH_TOKEN`, не выводится. |
| Исполнитель | `scripts/merge-engine/engine.mjs`, `scripts/merge-engine.mjs` | Проверка доступа, сводка, проверка PR, слияние, удаление ветки, проверка main и публикации, журнал. |
| GitHub Actions | `.github/workflows/merge-engine.yml` | Запуск по кнопке и сводка по расписанию (каждые 6 часов). |
| Панель | `studio/merge.html` | Merge Control Center: состояние PR, CI, main и публикации из общедоступного API GitHub. |

### Обязательные условия
1. PR из этого репозитория.
2. Целевая ветка — `main`.
3. Все проверки CI завершились успешно (перезапуски учитываются, незавершённые — запрет).
4. Нет конфликтов с актуальным `main`.
5. Слияние не убирает из `main` файлы и экспортируемые функции и не удаляет больше 120 строк.
6. В добавляемых строках нет токенов, ключей, паролей, e-mail и телефонов (в тестах допускаются явные заглушки).
7. `npm test` и `npm run build` проходят на результате слияния с актуальным `main`.
8. PR не черновик.
9. Не затронуты чувствительные файлы (`.github/`, `wrangler.*`, `package.json`, авторизация, миграции, `.env`) — либо владелец поставил метку `merge-engine: reviewed`.
10. Squash разрешён настройками репозитория.

Устаревшая ветка (отстаёт от main или давно не обновлялась) — предупреждение, а не запрет: тесты всё равно запускаются на результате слияния с актуальным `main`.

### Защита
- Слияние только с `sha` проверенной головы PR: если в PR добавили коммит после проверки, GitHub ответит 409 и слияния не будет.
- Повторное слияние той же головы пропускается (журнал и проверка `merged`); в Actions — `concurrency: merge-engine`, локально — файл блокировки.
- Без `--execute` (в Actions — без `execute: true`) выполняется только пробный прогон.
- Нет `--admin`, принудительного push, изменения правил защиты и настроек доступа.
- Удаляется только ветка этого же репозитория: не защищённая, не `main`/`master`/`gh-pages`, не используемая другим открытым PR.
- После слияния: main сверяется с коммитом слияния; публикация (`pages.yml`) запускается явно, потому что push от `GITHUB_TOKEN` её не запускает. Сайт считается опубликованным только при успешном завершении этого запуска.

## Запуск

```
node scripts/merge-engine.mjs doctor
node scripts/merge-engine.mjs status
node scripts/merge-engine.mjs check 45
node scripts/merge-engine.mjs merge 45            # пробный прогон
node scripts/merge-engine.mjs merge 45 --execute  # слияние (нужен GITHUB_TOKEN)
```

В GitHub: Actions → Merge Engine → Run workflow → `command`, `pr`, `execute`.

## Проверка доступа (17.11.2026)

| Что | Результат |
|---|---|
| GitHub CLI (`gh`) | не установлен на рабочем компьютере |
| Авторизация API | токена нет: доступно только чтение |
| Репозиторий | доступен (публичный) |
| Защита `main` | выключена: обязательные проверки GitHub не требует |
| Способы слияния | без токена GitHub их не показывает |
| Claude Code | работает как CLI на компьютере владельца, не как GitHub Action |

Чтобы исполнитель мог сливать, ничего дополнительно выдавать не нужно: workflow использует встроенный `GITHUB_TOKEN` с правами из блока `permissions`. Если в настройках репозитория (Settings → Actions → General → Workflow permissions) разрешено только чтение, явный блок `permissions` в workflow всё равно даёт нужные права для личного репозитория. Рекомендуется включить защиту `main` с обязательными проверками `test (20)`, `test (22)` и `e2e`: тогда GitHub сам не даст слить PR с упавшим CI — даже вручную.
