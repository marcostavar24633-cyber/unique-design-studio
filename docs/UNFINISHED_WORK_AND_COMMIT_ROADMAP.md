### Особое внимание: PR #99

Зафиксирована нестабильность E2E-теста:

- один запуск CI прошёл успешно;
- другой запуск на том же HEAD завершился ошибкой E2E;
- в неуспешном запуске проверки сообщали о потере AI-анализа аудитории при JSON-экспорте и после импорта с повторным экспортом.

Не отключать и не ослаблять тест ради зелёного CI. Найти источник нестабильности, повторить сценарий и подтвердить исправление несколькими прогонами.

## 4. Правила выполнения

- Не менять `main` напрямую для функциональной разработки: использовать отдельные ветки и PR.
- Один логически цельный коммит — одна понятная задача.
- Не создавать дублирующие коммиты для уже реализованного в открытых PR функционала.
- Перед изменениями изучать текущую реализацию, тесты и зависимости.
- Запускать относящиеся к изменению тесты до коммита; перед слиянием проверять полный CI.
- Не отключать тесты для искусственного получения зелёного статуса.
- Не удалять существующие проекты, примеры, пользовательские данные и рабочие сценарии.
- Не подменять реальные функции демонстрационными заглушками.
- Не выдумывать характеристики, цены, отзывы, сертификаты или результаты анализа.
- После каждого этапа сообщать: что изменено, какие тесты прошли, что осталось и какие PR/коммиты затронуты.

## 5. Условие завершения

Работа считается завершённой не по количеству коммитов, а когда:

- открытые PR проверены и либо безопасно слиты, либо снабжены конкретным списком блокеров;
- CI стабильно проходит;
- основные действия интерфейса действительно работают;
- проекты сохраняются и восстанавливаются без потери данных;
- генерация выдаёт отдельную концепцию для выбранной ниши;
- изображения и адаптивность проверены на целевых экранах;
- документация соответствует фактическому состоянию кода.
